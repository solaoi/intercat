M4は仕上げ・分岐の残りを作る。範囲と完了条件は[milestones.md](milestones.md#マイルストーン-4仕上げと分岐)、
仕様の正本は[design.md](design.md)とする。M1〜M3で受け入れた部分は再計上しない。

### V54：filter・LFSの隔離したチェックポイント

通常の保存と、別のオブジェクトの置き場を使う保存で、同じ木ができた。
変更したファイル・変更していないファイル・削除したファイルを含めて照合した。
元のindexとHEADは変わらず、sandbox内から元のオブジェクトを読もうとすると拒まれた。
LFSのcleanは専用の置き場所で動き、過去のLFSの実体はそこへ写らなかった。

統合用の独立したリポジトリへは、その木から参照するGitオブジェクトとLFSの実体だけを渡した。
sandbox内の展開と、Checkの前後に相当する`add -A`が通り、変更後のLFSの実体も保存できた。
初回はダミーfilterのsmudgeの設定が不足して展開に失敗した。設定を補い、再実行して受け入れた。

実行：`tools/probe_git_checkpoint.py`。
証跡：`research/verify/v54-checkpoint-20261108-02/verification.json`。
検証した[Git LFS 3.8.1](https://github.com/git-lfs/git-lfs/releases/tag/v3.8.1)は、公式配布物のSHA-256と照合した。
実行ファイルは管理外の`.tools/`に置き、全体のGit設定は変更していない。

### V60：認証と通信を切ったpre-push

独立したダミーHTTPSサーバーとcredential helperで、sandbox内からローカルbareへPushできた。
専用のssh-agentとダミー鍵でも、ローカルSSHサーバーを介したPushが通った。
利用者のcredential helper・SSH鍵・ssh-agent・known_hostsは使っていない。

pre-pushにはremote名とURL、Gitと同じ形式の標準入力を渡した。
通信を許可しないプロファイルでhookが通り、同じ制約での接続は拒まれた。
HTTPS helperには、macOSの公開SSL設定の読み取りが必要だった。
初回はその読み取りで止まり、許可する場所を追加した実行で受け入れた。

この試験の送信側は、通信を許可した方式検証用のプロファイルだ。
送り先を固定する製品のプロファイル、宛先変更の拒否、外部の認証サービスはまだ受け入れていない。
終了時に、試験用サーバーとssh-agentを止めた。

実行：`tools/probe_git_push_auth.py`。
証跡：`research/verify/v60-push-auth-20261108-02/verification.json`。

### V62：LFSを先に送るPush

## リポジトリの形式（2026-11-08、受入済み）

sparse checkoutの開始時の拒否を外した。cone・非coneの判定は、既存のgixのsparse用APIを使う。
sparse-indexは元を変更せず、保存した木からメモリ上で通常のindexへ展開する。
一時indexでは手動の印とstatのキャッシュを外し、sparseの型の外だけskip-worktreeを付け直す。
型の外の未展開ファイルは保持し、展開して編集したファイルと、型の中の削除は保存する。
元のindex・sharedindex・HEADは変更しない。

人のsparseなチェックアウトから、プロジェクトの選択・ワーカーの準備・保存までの4形式も確認した。
sparseなワーカーの変更は、Check・Commitまで通り、未展開の追跡ファイルも残った。
元のチェックアウトにファイルを展開したり、indexを変更したりしていない。

入れ子のリポジトリは、無視規則を使うgixの走査とindexのgitlinkで検出する。
隠しrefを作る前に保存を止め、対象のパスとExclude it / Stopのカードを出す。
Exclude itの選択はトラックごとにDBへ保存し、次の保存にも使う。
空のリポジトリもGitのaddより先に検出し、除外したパスはaddの対象と一時indexの両方から外す。
ワーカーがgitlinkをステージしても、元のindexは変更しない。

保存を待つ間もホストの制御は続け、Stopは待機を保つ。
除外を選んだ後は、その保存だけを再試行する。Stopで保留した次の依頼は送らない。
判断はカードのIDと版に結び付ける。同じ保存で次のパスが問題になっても、古い判断を流用しない。
再送は同じ操作IDを使い、DBへ保存した判断と再試行の受付を操作記録で結ぶ。

カードは100%・200%で、理由・除外の範囲・操作へスクロールして到達できるかを確かめる。
200%で固定ボタンが説明を隠したため、このカードの固定配置を外した。
小さい表示では、既存の承認返信と同じようにヘッダーを畳む。
ボタンの説明には対象のパスと除外の範囲を結び付けた。実VoiceOverの受入とは区別する。

この項目の実機検証時のDBの版は86。後続の分岐の指示と分岐元の記録では88へ進めている。既存の方針に従い、旧版への読み替えや自動移行は追加していない。
検証にはすべて新しいダミーDBを使い、利用者のDBは変更していない。

## 分岐時の指示（2026-11-08、受入済み）

選んだ集合は、開始操作に属する隠しrefとGitのblobで保持する。

## filter・LFSの接続（受入済み）

小さなダミー実体で、ポインタの抽出、SHA-256と大きさの照合、APFS clonefileによる転送を検証した。
必要な実体だけを転送し、元と写しをそれぞれ変更しても他方の内容は変わらない。
欠落・破損と、オブジェクトへのシンボリックリンクは拒む。破損した既存の実体は上書きしない。

チェックポイントのcleanと、Checkのsmudgeは専用のLFS保存先を使う。
Checkで作った実体は、コミットのGitオブジェクトを取り込む前に、元の実効の保存先へ戻す。
チェックポイントの操作記録にも保存先を固定し、再開時に参照する実体を照合する。
設定と操作記録の形を変えたため、DBはschema 89とした。旧版の移行は追加しない。

秘密の検査は、LFS本文の追加行も対象にする。Checkの環境変数の値を含む行を検出できた。
バイナリも既知の値は検査し、一般のルールで検査しきれないパスを`LFS binary not scanned`で示す。
本文を読む前に大きさを検査し、既存の64 MiBの検査上限を超える入力では完了扱いにしない。
本文そのものや検出した値は、検査結果の記録に含めない。

開始時のclean検査は、同じ隔離snapshotの経路へ移した。
実indexは変更せず、ステージ済みの変更と未追跡のファイルを拒む。
手動のassume-unchangedとskip-worktreeは、starting pointの規則どおり維持する。
分岐の指示を検査する処理も、同じ正規化を使う。
この段階の関連41試験が通り、その後にworktreeの展開と製品の経路の受入も完了した。

その後、workerの初回展開も隔離clone経由へ統一した。
設定と必要な実体を用意してからworkerのファイルを展開し、デーモンが実indexを確定する。
元のindexとHEADを変えず、filterの変換とLFSの本文を持つworkerを作れることを確かめた。
`npm run setup:tools`で固定したGit LFSも用意し、アプリから起こすデーモンのPATHへ足す。
全体のGit設定は変更しない。

LFSの保存からCommitまでと、Commit直前に実体を消す形も通過した。
欠落時はブランチを進めない。Checkの前の欠落はenv-failedとし、ローカルで取得するよう表示する。
Check用の環境変数の値を含むLFS本文では、Secret foundで止まり、値は記録に残らない。
選んだCheck用の値の指紋は、Commit直前にも固定した設定と照らす。
バイナリの検査範囲の表示は100%・200%で通過した。

公開済みの先頭と系統をセッションIDとフォルダIDの組で保存し、Commit・Push・合わせ直し・Restoreの照合もその組を使うようにした。

既定のrefが同じ構成で、両方のCommitが完了し、Gitの先頭と保存済みの系統が各フォルダの内容に一致した。
元のHEADとindexは変わらず、2つのローカルbareリポジトリへのPushも通った。
片方のrefだけを更新した状態と、更新前の衝突からの復旧も引き続き試験した。
Git更新後にダミーDBへの記録を失敗させると、Commitは理由付きの復旧待ちになった。原因を外し、同じ操作を再試行して完了した。
