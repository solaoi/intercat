## 現在動くもの

- バックアップ復旧：保存したファイル比較とセッション別の方針を再検証し、旧履歴を廃止して新セッションへ引き継ぐ。復旧用チェックポイントと外部確認の確定、途中取消し、応答を失った再試行、確定待ちの所有プロセス停止まで接続した。

- `services/editor`：ローカル Glimmer の `/decide`。一つの要求で一度 prefill し、同じ KV cache で後続の段を読む。候補すべての対数確率と、温度を適用した候補内の確率を返す。呼び出し間の接頭辞 cache は使わない。モデルは既存のローカルディレクトリに限る。
- ローカル Editor の起動管理：Rust デーモンが Python とモデルの場所を SQLite に保存し、プロセス・HTTP 受付・モデル読込の3状態を追う。UI の Configure editor で選べる。落ちたら 1 / 2 / 4 秒を空けて3回まで再起動し、置き換えたプロセスの古い判定は破棄する。仮想環境の Python はシンボリックリンクの呼び出しパスを保つ。モデルが消えても RPC 自体は起動する。
- 同じサービス内の推論キュー：GPU を一つのスレッドが扱う。判定が来ると背景生成を prefill の区切りか token の区切りで中断し、途中の文章は採用しない。
- `crates/intercat-git`：Git CLI を呼ばない管理用の操作。blob・木・commit、別の index からの木、期待値つき ref 更新、merge-base、3-way マージ、統合 clone からの取り込み。ref の更新は Intercat の名前空間に限る。
- Commit の入力固定と統合計算：認証済みの `integration.command` RPC から、セッションごとに一つの仕事を開く。完了記録のあるチェックポイントだけを SQLite で固定し、Git から読んだ基点・統合先もマージ計算の前に保存する。開き直しでは新しいターンを混ぜず、Refresh で版を進める。トラックの除外、衝突したパスと先行トラック、変更なしの判定、途中再開、古い版・重複操作の拒否まで接続した。`Prepare` で候補作成と Check を始め、結果を同じ仕事に保存する。メッセージ本文の編集と、確認した候補をセッションのブランチへ確定する処理も RPC に接続した。非モーダルの Commit シートから操作できる。
- Commit 向けの隔離実行基盤：`checkout.rs` に、固定 SHA だけの浅い clone、設定を移してからの木の展開、通信なしの Check 実行、出力上限、タイムアウト・取消・実行 future の破棄時の子プロセス停止を追加した。Commit シートの候補作成から利用する。実際の Node 24 と `npm test` を使ったダミー Check は通る。
- Commit の修正結果の取り込み基盤：失敗した候補の専用 clone で編集を受け取り、修正を担当トラックのコミットに戻して後続の寄与を再適用する。最終の木が一致しない場合は担当を後ろへ移す。実コミットの再構成・秘密検査・Check まで検証済み。修正 Run の永続化と開始予約、専用ホストの接続・終了・再開、ターン送信・承認・質問・Stop の実行ループを追加した。スケジューラ・共有実行枠・結果の取り込み・Remove と修正依頼の UI を接続し、修正後の再ビルドでも編集を保持する。
- Commit の内容検査：固定した gitleaks 8.30.1 を、各コミットの親との差分と hook 後の最終メッセージに適用する。検出時は Check の前に止め、該当コミットを元の object DB に取り込まない。Check・hook・依存導入の出力も保存前に同じ規則で隠す。検査結果は版・木・メッセージ・値の指紋に結び付け、場所と規則だけを公開する。Keep はシートへ接続した。Remove と Check environment の取得・注入は未接続。
- Git の同期：オブジェクトと木の内容、pack、ref と親ディレクトリに明示的な `F_FULLFSYNC`。失敗はエラーにする。worktree の隠し ref では SQLite の意図記録に接続済み。チェックポイントでも、到達するオブジェクトの同期 → SQLite の意図 → 隠し ref の同期 → 完了記録の順を使う。
- `crates/intercat-daemon`：ユーザー単位の lock、専用スレッドでの SQLite 書き手、操作 ID ごとの意図の保存と重複検出、Stop と開始の競合を処理する状態遷移、非同期の MSP 接続。実ホストの initialize → session/start → skill/list → 正常終了を通した。
- 開発用 `diagnose-turn`：専用カタログの intercat-report を添え、実ワーカーの1ターンを実行する。開始と許可は記録してから送り、受信は別に記録する。固定したテストコマンドだけを一度許可する診断用で、製品のポリシー核・UI の代わりにはしない。
- detached worktree：sandbox-exec 内の Git で作り、checkout 前に LFS/filter・submodule・未解決の index を拒む。元の checkout と index は変更しない。オブジェクト同期 → SQLite の意図 → 隠し ref の更新・同期 → 完了記録を接続した。AGENTS.md 等は階層と優先順位を保持して収集し、内容のハッシュとともに記録する。
- Electron の舞台プレビュー：PixiJS のレーン・一歩・点線の予定、選択の grid、↑↓ / 1–9 / ⌃Tab、予定の削除、時間のページ送り。データは明示したサンプルで、モデルに送信しない。Monaco の差分と pdf.js の実 Worker を同じ CSP で検証した。
- 実タイムライン：MSP の受信イベントと、item ID・revision の投影を一つの SQLite トランザクションで保存する。生成とツール群を一歩として番号を付け、同じ受信列から同じ番号・区間を再構成する。高い revision だけで差し替え、主セッションの reminderChild は実行中の一歩に含める。userMessage の受領で入力を landed にし、開始応答が後から来ても戻さない。幅にはスリープ中も進む mach_continuous_time を使い、デーモン再起動をまたぐ時間は非負の壁時計差として「approximate」を付ける。舞台のクリップから実際の本文・ツール出力・変更 hunk を開く。差分は item/readOutput で最大1 MiB を取得して保存し、ホストが返したローカルパスを直接読まない。ストリーム断片の本文は保存しない。通常の状態取得には短い要約だけを返す。
- プロジェクトの設定：M1 の一フォルダを UI から選び、根・共通 Git ディレクトリ・開始コミットを保存する。未コミットの変更（未追跡を含む）・未解決の index・非対応の checkout を拒む。Git の表示設定が未追跡を隠していても検査する。利用者の index・HEAD は書き換えない。選択後に HEAD が進んでも、作業ツリーの作成には保存したコミットを渡す。セッション名は最初の入力から保存し、直近100件の入力表示とは独立させた。
- ワーカーの起動設定：UI の Connect workers で選んだ Muse を、固定 SHA-256 と版を検査して専用ディレクトリへ複製する。既存の Muse サインインを使い、ログインシェルの PATH を取得して保存する。トラックの作業ツリーでホストを起動し、initialize の fingerprint、権限プロファイル、intercat-report を確かめて ready にする。資格情報の値は DB に入れず、必要なパスだけを保存する。
- 通常のワーカー実行：保存した入力をトラックに送り、開始の予約を SQLite に記録してから turn/start する。実行上限は4本。通常のコマンドは核が判定し、push・削除・権限昇格・未知の操作は、要件 ID と利用できる選択肢を確かめた承認カードにする。カードは本文を末尾まで見てから Allow once を押せる。Stop は記録の応答を待たずに優先経路で interrupt を送り、選んだワーカーだけを止める。完成した報告を机に表示する。
- 承認ポリシーと Stops：Settings · App に Irreversible only / Every approval を追加し、次の承認要求に適用する。Muse の promptUnmatched は変えず、SQLite の書き手が保存済みの Stops で判定し、`policy.evaluated` と要求ごとの判定を保存してから許可する。SQL・Redis・mongo・フレームワークのリセット、デプロイ、HTTP の書き込みやメール、予約・切り離し・入れ子のエージェントを既知のパターンで判別する。ネットワークは localhost・registry に加え、Git の fetch / push と URL 書き換え後のホストを読む。表示専用の origin は判定しない。予定実行・切り離しには Allow once を出さず、RPC からの許可も拒む。認識できないシェルの包みは確認に回す。
- MSP の入力質問：ホストの質問 ID・選択肢をそのまま持つカードを追加した。単一選択・複数選択・自由回答・注記を検証し、全問の Send answers、Explain instead、確定済み部分を伴う Stop を扱う。受信直後に userInput/engaged を優先経路で送り、回答の完了は userInput/settled まで待つ。ワーカー状態の保存要求は actor から順に書き手へ渡し、遅い非同期処理が古い質問状態を書き戻さないようにした。古い版・二重送信・遅れた確認で新しい質問を上書きしない。これは MSP 入力要求の経路で、通常の報告文に書かれた質問は次の経路で扱う。
- 報告の質問と返答：`Waiting for you:` の行を規則で保存し、行がない最終報告はローカル Glimmer に問い合わせる。判定未完了・不正応答・10秒超過を「質問なし」にせず、確認カードで止める。質問の ID・版・返答の入力 ID を保存し、返答は分類器を通さず元の質問へ固定する。質問が複数あればその順に返答を送り、返答が実際に送られるまで通常の後続を止める。Take back・送信失敗・質問の改訂で待機を外さない。別の窓の返答に置き換えられた入力は orphaned にする。判定前に保存待ちの報告も実行の関門に含む。
- Effect の記録と表示：ポリシーが分類した要求を、ホストの段ごとの許可・実際の開始・終端 item と結ぶ。許可だけでは作らず、単なる権限拡大や復元可能な削除も含めない。開始後の通信先の拒否を反映し、終了コードが 0 でも成功扱いにしない。接続断や再起動で途中のものは結果不明にし、自動再送しない。クリップの外向きの印と詳細、ワーカーの報告脇に表示し、ファイル復元では取り消されないことを示す。保存した入力イベントだけから Effect を作り直せる。
- 削除前の退避と復元：同じチェックポイントの木の作り方を使い、削除直前の tracked / untracked ファイルを専用の隠し ref に保存する。対象の内容・種別・実行属性を実際の保存結果と照合し、全対象を戻せる削除だけを自動許可する。Every approval では確認を残し、許可直前に取り直す。ignore 対象、外部、symlink を経由した親、glob、別の Git source・cwd、stash など判別できない範囲は確認する。クリップの「Before deletion」から保存済みパスを復元でき、復元前にも退避するので戻せる。元の index・HEAD・checkpoint の分岐点は進めない。復元中と未完了の復元がある間は新規作業を止め、再試行では同じ操作 ID を使う。
- ターン末尾のチェックポイント：実 worktree の index（split index も含む）を gix で読み、一時の単独 index にする。通常 checkout の assume-unchanged / skip-worktree を外し、別のオブジェクト置き場で sandbox 内の add --sparse -A を動かす。秘密の型は、トラックの基の木に無いパスを一時 index から除く。write-tree --missing-ok の後、到達する木だけを gix で取り込み、turnId 付きの隠し ref を保存する。元の index と HEAD は変更しない。保存完了を記録してから同じワーカーの次のターンを許可し、報告には SHA を付ける。残るプロセスと未解決パスをチェックポイントに記録する。疎な checkout は引き続き拒否する。
- ワーカーの待機と終了：ホストの待機状態と sessionId・PID／開始時刻を保存する。デーモンの正常終了時はホストと記録した子を止め、正常終了後は同じセッションへ resume する。待機中のホストが落ちた場合、後始末を確認できれば Retry worker で戻れる。後始末が不明なら needs-recovery で保留する。実行中のターンの復旧とはまだ結び付けていない。
- 作業ツリーの自動準備：待機入力からできたトラックごとに、保存した開始コミットで detached worktree を作る。セッションの slug は既存のブランチと隠し ref を調べて空いている名前を予約する。予約用オブジェクトを同期し、SQLite の意図を保存してから ref を更新・同期する。再起動時は同じ操作 ID で残った準備を読み直す。失敗は机のカードと Retry preparation に出す。
- 入力の分類：Put / New track で保存した入力をバックグラウンドで `/decide` に送り、有限の選択肢を操作・宛先・時機へ戻す。New track は独立した開始条件だけを読み、錠の宛先は動かさない。候補全体のスコア・確率・選択値を検証し、生の判定は SQLite に保存する。UI は実際に保存した待機トラックと入力を表示し、プレビューのサンプルは混ぜない。
- 判定の保留：Editor の不在、遅延、不正応答、行き先の不明を送信の許可にしない。推論サーバーは GPU 処理に入った時点で HTTP ヘッダーを返し、その受信後 1.2 秒で待機を打ち切って確認カードにする。キューの待ち時間はこの期限に含めない。遅れた応答でカードを下げたり、投入したりしない。
- 確認と取消：カードから宛先を錠にして再判定、明示の Hold、Start による再判定、Edit、Cut ができる。Hold は再起動後も維持する。操作 ID と revision を同じトランザクションで検証し、取消や回答より古い判定は捨てる。未完了の reading だけを起動時に読み直す。
- UI とデーモンの RPC：0700 の専用ディレクトリ内の 0600 Unix socket、getpeereid と最初の token による認証、64 KiB の入力上限。token は macOS Keychain の `Intercat / rpc.ui` に保存し、起動時にパイプでだけ渡す。Node を使うのは main/preload で、renderer には用途を限った API だけを公開する。下書きの保存と opId の受理を同じ SQLite トランザクションで行い、再送は元の結果を返す。
- プロセス追跡：libproc の PID・開始時刻（µs）と、ホストの印・記録した親子関係・グループで照合する。所有情報を非公開ファイルに保存し、デーモン再起動後の Stop here でも照合する。記録外の PID には信号を送らない。受信や記録の経路が失敗しても、書ける stdin へ停止を送る経路を持つ。
- 受信の保存：delta 本文は保存せず長さだけを記録し、完成した本文を保存する。長すぎる文字列は頭と末尾を残す。既知の秘密文字列を隠す処理は追加したが、ユーザーからの秘密入力と Privacy gate はまだつながっていない。

UI の入力から分類・作業ツリー・通常のターン実行・承認・Stop・チェックポイント・Commit・隔離した修復 Run まで接続した。M1 はまだ完了していない。以下の残件の列挙は、後続マイルストーンの範囲も含む。Privacy gate、Meta の認証画面、秘密入力とホストへの受け渡し、削除対象の解析範囲の拡大、Effect 表示の範囲と結果照合の拡張、VoiceOver の実読み上げ、自由形式の仮定・選択肢の抽出、Check environment と未対応の依存経路、バックアップ復旧は残る。保存結果から対象全体の復元を証明できる削除は自動許可し、それ以外は確認する。trim は、対象ターンを止めてチェックポイント保存後に訂正を送る経路へ接続した。自然言語の command は判定の記録までで、画面の Commit 操作とは未接続。通常ワーカーは切断後に最大3回の自動再接続を試み、状態を照合できないときは保留する。修復 Run の自動再接続、チェックポイント失敗後の復旧・電源断と、疎な checkout・LFS は未実装または未検証。

特定の一歩の後という条件は対象選択を求め、動いていないトラックの trim も確認で止める。計画・スキル選択・候補外の再検索と、判定品質の校正は残る。背景生成は内部の検証用 API で、生成用の HTTP API はまだない。MSP の受信は記録の書き手から独立しているが、delta 本文の除去と負荷時の破棄、記録完了まで含む容量制御、上限超過時の割り込みは接続した。大きな完了本文が並ぶ間の承認の優先処理と、全メソッドの型付けは残る。タイムラインは直近500クリップ・200発言を返す。ツール群は受信済みの非終端 item が全て終わった時点で区切るため、一般的な並列呼び出し全ての順序を保証する検証は残る。ターン後も inProgress の bash は別の shell クリップにするが、閉じるのは後続の終端 item による。プロセス群との対応付け・終端イベント欠落時の復旧は未完了。

### プロセス所有情報の保存と再起動後の停止（2026-11-04）
