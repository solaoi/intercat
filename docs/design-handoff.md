# Intercat — 設計引き継ぎ

Intercat（intercut ＋ 猫）は、AI エージェントと働くためのノンリニア・マルチエージェント・タイムラインエディタ。macOS アプリ（Electron）として作る。Muse の multi-agent を見えるようにして、走る前に編集する（封じるのではない）。

マイルストーン1の依頼・承認・停止・復旧・Check・Commitと全60条件の受入を完了した。次はマイルストーン2のEditorを進める。実機の受入記録は [M1受入条件](m1-acceptance.md)、起動方法と実装履歴は [実装の進捗](implementation.md) を参照。

Meta Hackathon 向けの設計、実機検証、macOSアプリの実装をこのリポジトリで管理する。

文中のパスはリポジトリのルートを基準とする。

## 最初に読むもの

1. この文書の「決まっていること」で、全体をつかむ。
2. 設計書 `docs/design.md` の「0. この文書について」で、用語を確かめる。
3. 板（`design/boards-png/`）を見ながら、設計書の 1〜7 節（何を作るか・画面）を読む。

## 正本と判定の原則

- 正本はこのリポジトリ。設計書は `docs/design.md`、板は `design/boards/*.html`（PNG はそこから描く）。
- どの記述も正しい状態に保つ。食い違いを見つけたら、どちらかに決めて両方の箇所を直す。
- 板とズレたら、板が正。
- 例外は、板を描き直すときに直すと本文に書いた箇所だ。そこでは本文が正で、`design/boards/index.json` のその板に `stale` として記録する。
- 板は 64 枚、設定は 7 ページ（10a〜10g）。設定のシートの上で、適用先（App か Project）を選ぶ。

## 公開の方針

- 2026-11-05 のハッカソンへの提出で、リポジトリ（https://github.com/solaoi/intercat）を公開した。提出の版は `6375ec6` で、タグ `hackathon-submission` を付けた。
- 公開に当たる操作は、引き続き人がそのつど明示したときだけ行う。たとえば次のもの。
  - push（タグを含む）と、公開の remote を足すこと
  - gist・pastebin・claude.ai の Artifact・共有リンクに、中身を載せる
  - issue・PR・SNS・ブログ・チャットに、中身を貼る
  - パッケージやアプリを publish・配布する
- 次の二つは公開しない。`research/`（調査と検証の生ログ。手元のパスや個人の設定が入る）と、`movie/`（動画の制作物）だ。どちらも `.gitignore` で管理の外に置く。
- 公開していない中身（上の二つなど）は、外部のサービス（Web 検索、翻訳、Web の生成 AI など）に貼らない。調べものは、一般的な語だけで引く。
- 実装の試験で使う remote は、手元の bare リポジトリにする（[docs/milestones.md](milestones.md)）。
- Muse Code と Model API に渡すコードとプロンプトは、公開ではないが、Meta に送られる。Contributor mode がオンなら、Meta がモデルの改善に使うことがある（「現在地」）。

## 決まっていること（要点）

一つの決定を一、二文で書く。数字・フラグ・根拠は、設計書と research/verify にだけ置く。括弧の中は設計書の節と検証項目。

### 画面の三層（3 節）

- サイドバーは「どこ」（プロジェクト → セッション）を示す。開いているセッションは、人の操作でしか変えない（3.1）。
- 舞台は「誰」（トラック × 実時間）を示す。机は「何」を示し、ログ・Needs you のカード・帯・Editor の行・入力欄を持つ（3.2）。
- 承認のカードは、対象のパス・操作・戻せるかどうかを省略せず、折り返す。4 行を超えたらカードの中でスクロールし、末尾を見るまで Allow once は押せない（3.1・17 節）。
- 最小の窓（1040×760）では、帯を一行にし、入らないチップは「+N」に入れる。承認のカードが場所を要るときは、台本を一行に畳む（3.1、板 13）。帯の先頭には、トラックごとの次（「A’s next」）を並べ、全体の順は約束しない（3.2）。
- 入力欄の下の状態の行は、下書きの宛先のトラックのモデルと effort を示す。閲覧中のトラックのものは、台本の見出しの右に出す（3.2）。
- 入力欄の右端は、文字が無いときはマイク、文字があるときは送信ボタン（↑）だ。New track は、↑ の ▾ と ⌘⇧↵ に置く（3.2）。
- サイドバーの先頭には、どの画面にも Home の行（⌘0）がある（3.1）。
- Home（⌘0）は、セッションを選んでいない状態だ。全セッションを最後に動いた順に並べ、Needs you に全セッションのカードを集める。ポインタが一覧の上にある間とフォーカス中は、並びを動かさない（3.1）。
- 画面と描画は、実際に走る本数より一桁多い量に耐えるように作る。レーンの密度は三段で、本数が増えても並びは作られた順のままだ。20 本を超えたら folded が既定で、押せる対象は縦横 24px 以上にする（絵が小さい ■ や × も、当たりは 24×24）。窓が低くて普通の配置が入らなければ、レーン 1 本・カード 1 枚・帯 1 行の小さい配置にする（3.1）。短いクリップが続く所は「5 steps」の札にまとめる（3.4・15 節）。

### プロジェクトとフォルダ（5 節）

- フォルダは、リポジトリの根と共通の Git ディレクトリで見分ける。同じリポジトリの二つ目のフォルダ（サブフォルダや別の worktree）は足せない。
- 言葉が先で、フォルダは文脈だ。言葉の出どころは声・文字・課題の三つで、v1 は声と文字だけ。
- プロジェクトはフォルダを 0〜8 個持ち（v1）、セッションがそれを引き継ぐ。Muse Code のホストは、トラックごとに一つ立てる。シェルのプロセスを、トラックに結び付けるためだ（15 節）。
- Move to project は、移動先がセッションのフォルダを全部持つときか、フォルダの無いセッションだけだ。保留してホストを止め、所属を変えてから、移動先の設定でホストを立て直す（5 節）。
- 1 セッション＝1 ブランチ＝1 PR だ。フォルダが複数なら、フォルダごとに一組ずつ持つ。
- slug はセッションを始めたときに決め、後で変えない。名前は表示だけで、Editor が付け直してよい。
- Git の無いフォルダでは、今のファイルを入れた初期コミットを作る。追加の画面に「starts version history here」と取り込む範囲を出す。.gitignore が無ければ、一般的な型と秘密ファイルの型で作り、仮定のカードにする。50 MB を超えるファイルは、初期コミットにも starting point にも入れず、元の場所で参照だけにする（5 節）。
- 既存のリポジトリに未コミットの変更があれば、始めるときに一度だけ聞く。含めると、セッションのブランチの最初のコミットになる。人の作業ツリーと main には触らない（5 節）。

### ハーネス（15・17・22 節）

- Muse Code がワーカーのハーネスだ。Intercat は、複数の Muse Code を束ねる「指揮者のハーネス」になる（22 節）。
- Editor の本体・計画キュー・境目待ち・ポリシー核は、セッションデーモンに置く。UI（TypeScript と PixiJS。タイムラインは GPU で描く）は、デーモンのクライアントだ（15 節）。
- デーモンは Rust で書き、MSP のクライアントも自前で書く。Node で書いて後から移す道は持たない（15 節）。
- 公式の Rust SDK は、使うメソッドの一部を公開していないので、クライアントには使わない（㉜）。TS の `@muse-code/sdk` は、記録の再生で突き合わせるテストのオラクルにする（㉔）。
- 同時に走る本数の上限（cap）は、デーモン全体で一つだ。超えたトラックは planned のまま列で待ち、これは失敗ではない。数えるのはホストではなく、走っているワーカーのターンだ。Planner と Reviewer のターンは、別の上限（既定 2）で数える。枠は、ターンの終わりが分かった時点で一度だけ返す（取り戻した turn/unqueued を含む）。待機中のホストは、メモリが要れば古い順にすぐ止める（15 節）。
- ホストは、デーモンの stdio の子プロセスとして立て、利用者の TUI と共有する socket のデーモンは使わない。Planner と Reviewer は、書き込み・シェル・Web を切った読み取り専用のホストで走らせる（15 節）。
- 走らせる Muse Code は、Intercat が持つ検証済みの写し（1.4.14）だ。利用者のランチャーは、更新のたびに古い本体を消すからだ。写しの SHA-256・版・initialize の fingerprint が合わなければ、走らせない（15 節・㊸）。
- ワーカーのホストは、Stops の値に依らず承認モードを常に promptUnmatched にする。onRequest では、Muse が安全と見なした命令が要求なしに走るからだ（15 節・㉕）。
- ホストには、デーモンが作る専用の設定ファイルで、profile とほかの設定を渡す。ワーカーの profile は、`:ask-me` を継承した `intercat-worker` だ。読み取り専用のホストの profile も `:ask-me` を継承し、書き込みと shell はフラグで外す。利用者の settings は変えない。session/start の返事の profile が違えば走らせない（15 節・㉝）。
- ワーカーには、許可リストの道具だけを渡す。シェルで同じことをする道は残るので、ポリシー核が止める（15 節）。
- ホストの環境は、デーモンが空から組む。API キーで走らせると、キーはワーカーの環境から読める（従量では避けられない。15 節）。
- ワーカー内のサブエージェントと workflows は、提出までは止める。子のツール呼び出しが MSP に出ないからで、出るようになったら子レーンにする（22 節・㉗）。
- Contributor mode は鏡写しにし、プロジェクトごとに Off にできる。Off にしたら、そのプロジェクトの新しい投入を止め、ホストを立て直してから再開する（7 節）。Editor 自身の Image と Voice は常に標準で、Glimmer は Model API を通らないので対象外だ（7 節）。
- ワーカー同士は話さない。受け渡しは、Editor が要約と参照で行う（17 節）。
- Planner（熟慮）は Wonder が既定だ。E → C → R → S（ECRS）の順に問い直して、ステップを分ける（17 節）。
- 全ワーカーのターンに、組み込みスキル intercat-report を添付して、最後の返答の形をそろえる。報告の SHA は Editor が付け、言語は人が最後に使った言語に合わせる。変えたことの各項目には、理由を一句書かせる（17 節）。
- 判断は、投入の前に記録する。説明（line と detail）は後から付く（0 節）。根拠の無い反論（「まだおかしい」）は、止めずに、ワーカーが先に書いた理由と一緒に送り、理由が成り立たなくなった項目だけを直させる。「頑固になれ」とは指示しない（17 節。M2）。
- intercat-report はホスト専用の設定内に置き、ユーザースキルとして skill パートで指す。依頼文の末尾にも同じ指示を入れる。既定では project trust を付けず、AGENTS.md の指示はデーモンが適用範囲を保って添える（17 節・㊽）。
- デーモンは、起動の最初に取るユーザー単位のロックで一つに保つ。取れない側は、既存のデーモンへ接続する（15 節）。
- デーモンの RPC は、ユーザー専用のフォルダの Unix ソケットで通し、複数のクライアントが付ける形にする。ワーカーが Intercat に書き込む道は作らない（15・22 節）。接続には UI だけが持つ token を求め、ソケットのフォルダはワーカーのサンドボックスで拒む。状態を変える呼び出しは、操作 ID で一度だけ行う（22 節、V55）。
- Git の書き込みも、SQLite と同じく F_FULLFSYNC まで書き出す。git の CLI には同期の設定を付け、gix の振る舞いは V53 で確かめる（17 節）。
- 窓を閉じても、トラックは走り続ける。⌘Q のときだけ、続けるか全部止めるかを一度聞く（15 節）。
- Editor の状態は一つのループで変え、待ちのある仕事はループの外で行う。Check の最中でも、Stop と承認の答えは待たされない（17 節）。
- Stop everything の完了は、記録したプロセスの組に、生きたプロセスが無いことだ（18 節）。

### Editor の判断（9 節）

- 判断の語彙は八つだ（extend / fork / schedule / trim / park / ask / plan / command）。command はアプリの操作で、置き場所の判断ではない。command は実行の一歩手前まで準備し、確定は人のボタンかキーで行う。「push して」は Push の確認シートを開くまでだ。ボタンからの Push・Push to here・Open PR も、同じシートを開く（9.3・5 節）。
- 判定の境界は段ごとに当て、曖昧だった段だけを聞く。trim は確信が 0.8 以上のときだけ実行する（9.3）。
- 反射は生成せず、Glimmer のロジットで選択肢の確率を読む。判定は推論サーバーの端点 `/decide` で、全候補のスコアを一回の prefill で読む（9.3）。接頭辞のキャッシュは、判定が変わる原因が分かるまで使わない（9.3・㉞）。
- 600 字を超える貼り付けは添付に分け、打った文を判断の入力に残す。判断の入力はトークンで数え、予算を超えたらカードで一行の依頼を求める。声も同じで、文字起こしの全文は添付にする（18 節）。
- 置き方は二段だ。まず規則ですぐに置き、送る前に判定が返れば確定か置き直しをする。返らなければ、人が宛先を決めていない言葉は送らず、中立のカードで聞く。人が宛先を決めた言葉でも、操作の判定（command など）は待つ。Editor が使えない間は送らず、帯に一行を出す（9.3）。
- 計画は Plan（全体。id・rev・state）と PlanItem（項目）に分ける。Start plan の横に Review plan を置き、計画が二つ以上なら「Plans ▾」で選ぶ（9.8）。
- 主ストーリーラインの札は、結果の語で出す（「to A」「new track」「redirect A」「parked」「asked」「planned」）。内部の値と session/fork は fork のままだ。600 字を超えて貼った文には、送る前から「Keep as the request / Attach as reference」を付ける（3.2・18 節）。
- Try it two ways は、v1 では残す道を勧めない。結果と差分を並べるだけだ（12.9）。
- New track で送った言葉も、時機（Boundary）を読む。合図を待つものは「waiting for your go」、安全のための止めは「held」と、字を分ける（9.3）。
- トラック見出しの選択は閲覧で、宛先を決めない。文脈チップは「Editor decides」で、選んだトラックは判定の候補の上位に入る。錠は「Only A」・見出しの「Say to A」・レーンへのドロップ・Read as での選び直しだ。送るかどうかの表も、この宛先の種類で分ける（3.2・9.3）。
- チップの You said か Read as を開いている間、その言葉は送らない。窓が 10 秒ごとに延ばす。窓が切れたときと 30 秒延びなかったときは、送らずに「held · Start」にする（9.4）。
- Glimmer は Model API に無い。Editor は、この Mac の MLX（Local）の Glimmer を必須にする。Hosted（Modal）は、人が設定で選ぶ道だ（17 節）。
- Editor が使えない間（読み込み中、落ちた）は、ターンの開始だけを止める。Stop・承認の応答・画面のボタン・質問への返答は通す（9.3）。
- Decision には、規則で置いたか Glimmer が置いたかを残す。規則から判定への置き直しは、訂正率に数えない（9.3・17 節）。
- Home で話した言葉は、まず route でセッションへ振り分ける。送った後に人が別のセッションを開いていたら、自動では開かず、Editor の行で知らせる。その後、そのセッションの中でもう一度いつもの判断をする（9.3）。
- 走っているトラックへの言葉は extend で、境目はターンの切れ目だ。Editor が言葉を持ち、ターンが終わってから送る（9.4・④）。
- 送るかどうかは、表示の状態でなく実行の事実で決める。走っている turnId が無く、ターンの終わりを確かめ、チェックポイントの保存が終わったときだけ送る。承認待ちのトラックには送らない。ifBusy は送らず、Muse 側に並んだら turn/unqueue で取り戻す（9.4・㊵）。
- 答えを待つ質問は、報告の最後の固定の一行「Waiting for you: …」で読む。この行があれば、次の言葉も後続も送らない。この行が無い返答は、Glimmer の取り出しが終わるまで送らない（上限 10 秒。超えたらカードで聞く）。遅れて届いた質問は元のターンに結び付け、次のターンが走っていれば、working のまま「next waits for your answer」と出す。そのターンが終わってから止める（9.9）。質問への返答は、ほかの質問を待たずに質問の順に送る。
- 錠の言葉は、宛先が人の指定になる。Glimmer はその宛先を動かさない（9.3）。下書きが持つ宛先は錠と返答のカードだけで、見るための選択では変えない（3.2）。
- Editor の判断で走っているターンを止めるのは、trim だけだ。trim は turn/interrupt で止め、ターンが終わってから訂正を新しいターンとして送る。steer は使わない（9.4・④）。点線のクリップを切るのは、人の cut だ（9.3）。
- 人は ⌘.（今すぐ）と ⇧⌘.（このターンの後）で止められ、Glimmer が動いていなくても止まる。止めたトラックは waiting か done になり、境目待ちの言葉は「held · Start」で残る（3.2）。
- 状態の行の左の端に、走っている間は常に「■ Stop all turns · 2 sessions」を出す（全セッションを止めるので、範囲を字で示す）。その右に、選んでいるトラックが走っている間「■ Stop A」を出す。シートを開いていても見える（3.2）。Stop A は work の Run だけを止め、統合の直しは、レーンの下の細い行の ■ で止める。fix か merge の Run があるときだけ、ボタンは「Stop A · main work」になる。二つの位置は選択で変わらず、押せない時間も作らない。
- ⌥⌘.（Stop all turns。メニューバーの Agents）は、アプリを終えずに全トラックを止める。Resume を押すまで、何も新しく始めない。Resume は held の一覧を開き、Start all か項目ごとに始める。プロセスまで止めるときは、確認つきの「Stop all turns and processes…」を使う。ホストも閉じ、アプリは終えない（18 節）。
- トラックが多いときは、判定の前に候補を 8 本まで絞る。Glimmer が候補の外と答えたら、全文検索で候補を広げて二回目を待つ（17 節）。
- 確認モードでは、置く前に解釈を見せ、人の OK まで置かない。訂正率が上がると、このモードに入る。訂正は、明示（Read as と Mark as misread）と推測（Take back の後に、ほぼ同じ文を別の宛先へ）を別々に数え、確認モードには明示だけを数える。cut・Hold・Take back だけでは数えない（9.8・17 節）。抜けるのは、人の「Back to automatic」だけだ（23 節）。

### Editor の自律の段階（9.8）

- 黙ってやるのは、置く・反射の fork・言われた trim・同じ言葉の統合だ。Reviewer の blocking の指摘も、点線のクリップとして黙って置く。
- Planner の計画と新トラックは、置いて見せてから走らせる。既定では、人が帯の計画のチップの「Start plan」を押すまで走らない。帯で白いボタンは、これ一つだ。計画のタイルには Start を出さない。設定で、5 秒の猶予の後に自動で走る形も選べる（猶予は、計画が見えていて何もしていない間だけ数える）。計画への合意は、不可逆な一手の許可にはならない。計画の Hold は、自動の設定のとき、走り出す前のチップに出す。走り出した後の「Hold the rest」は、どちらの設定でも出す。計画の項目は、計画が開始できる（Start か猶予）ことと依存先の完了の両方が揃ってから走る。各項目は、題とは別に実行本文・制約・完了の条件を持ち、ワーカーには元の依頼の全文を送らない（16 節）。依存は配列で、全部が done で開始する。Planner は、セッションのブランチの先頭と、走っているトラックのチェックポイントを読む。送信ボタンの ▾ の Plan only（⌘⇧P）は、判定に関わらず実行を止める（9.8）。依存のある点線は、秒読みではなく「after A」と出す（9.8）。
- 点線のタイルを選ぶと、その項目の実行本文・制約・完了の条件と、元の依頼の一行が出る。Start plan は、見た版（Plan.rev）を始める（9.8）。
- Planner の計画は、置く前に決定的に検証する（参照先・循環・トラックとフォルダ）。不正なら一度だけ作り直させ、それでも不正なら走らせない（17 節）。継ぐ依存は、トラックの単位でも循環させない。錠の言葉から作った計画は、全部の項目を錠のトラックに置く（Plan.lockedTrack）。合わなければ「Unlock and split?」で聞く。依頼の添付は、Planner と各項目のワーカーに同じ写しで渡す（17 節）。
- Planner が時間内に返らなくても、走らせない。チップに Retry と Run as one job を出し、一つの仕事にするかは人が選ぶ（「まず方針を見せて」の計画では Retry だけ。18 節）。点線の依存は、依存先の項目が succeeded になったときだけ解く。結果は、報告の固定の一行「Result: done / partial / failed — 理由」で読む。failed や行が無いとき、cut・stopped・中断でも、後続は held にする。項目の続きと見なすのは、明示で結んだターン（項目の質問への答え・再試行・タイルを選んで話した言葉）だけだ。後続の差分は、継承の線を合わせた基点の木から取り、3-way を一度だけ当てる（13 節）。後続は、依存元のチェックポイントを土台にして作る（10.1）。
- 不要なクリップの削除などは、仮定して進め、仕上げで確定する。人なしに続けられないことは聞き、そのトラックだけを stopped にする。
- 済んだ作業の巻き戻しと、ファイル・トラック・言葉の削除はしない。

### 分岐（12 節）

- Muse Code の rewind は使わず、Branch from here に置き換える。rewind はファイルを戻さないからだ。
- fork は MSP の session/fork だけを使い、代わりの経路は持たない。
- 分岐点とチェックポイントの単位は、ターンの終わりだ。チェックポイントは会話の位置と、未追跡を含む worktree の SHA を一組で持つ（ignore の対象と worktree の外は戻らない）。次のターンは、その保存が完了してから送る（12.4）。
- 分岐した道（A′）は、元の道と並んで走り、親の許可を引き継がない。残す道は仕上げで人が決め、残さない道は幽霊レーンに退避する。A′ は、A の差分の基点を引き継ぐ（分岐前の未統合の変更を落とさない）。A′ の基点は、分岐元のチェックポイントに記録した基点（baseAt）だ。A′ を残して A を退避するときは、統合した番号が分岐元以上の A のコミットを取り消す undo を先に作り、A′ を自分の base から当てる。A の後半を継いだ後続は、シートで A′ に合わせ直すか外す（12.6）。退避する道が走っていれば、シートで予告し、Commit で Stop と同じ道で止める。Restore は元のトラックを戻す。置き換えで取り消していれば、L に undo を当てた木を基点に、今の先頭へ合わせ直す（12.8）。

### Commit（13 節）

- 統合 worktree は、セッションとリポジトリの組ごとに隠しで一つ持つ。ブランチを持つのは統合 worktree だけで、ワーカーの worktree は detached HEAD で作る（13・19 節）。
- 衝突は、固定したチェックポイントから作る一時の merge worktree で、後のトラックの merge クリップが解く。ワーカーの走っている worktree には触らない。解けなくても、トラックは止めない。失敗は統合の仕事の状態で、担当のレーンに「integration failed · needs you」の印を出す。解けなければ、人が解くか、もう一度走らせるか、後のトラックを今回の統合から外す（既定は無い）。提出とマイルストーン 3 では解かずに止め、外すか Discard で捨てる。外すときは、そのトラックから継承し、継承分が未統合のトラックも一緒に外す（13.3）。
- 統合の仕事はセッション×フォルダに一つで、各窓のシートはその状態を購読する。シートは舞台だけを覆い、机は生きたままだ。シートはモーダルではなく、⌃Tab で机と行き来できる（13 節）。
- シートを開いたとき、トラックごとに基点（base）・今回のチェックポイント・統合先の元を固定する。開いた後に終わったターンは、Refresh を押すまで入れない。
- まとめた結果をテストコマンドで Check し、通れば Commit できる。Check の結果は、検査した木に結び付ける。コミットは統合の作業場所（浅い clone）で `git commit` で作り、hook を通す。載せる 3-way は、作業ツリーに触れずに gix の木のマージで行い、merge driver は動かさない。展開は `read-tree --reset -u` で行う。Check の直前に、木に無いものを ignore の対象まで消し（`git clean -ffdx`）、依存を入れ直す。前のトラックの生成物を Check が読まないためだ。manifest・lockfile・導入の設定のどれかが変わっていれば、lockfile を変えない導入で依存を準備し、失敗は env-failed としてテストの失敗と分ける。Check の前と後に、ディスクと木の一致を確かめる。Check が追跡ファイルを変えたら、成功を無効にする。シートは、確認した版を窓ごとに持つ。別の窓などで版が進んだら、Review を押すまで Commit は押せない。Commit を押すと、ブランチを先に、統合済みの境界を後に進める。途中で落ちたら、操作のログから起動時にやり直す。押せば、残りの仮定は Keep になる（13 節）。
- シートのトラックの行は二段だ。入る分「Included · up to A:3」（入る最後のクリップの住所まで）と、走っている分「Not included · running now」を分けて見せる（13 節）。
- Intercat が作るコミット（初期・starting point・チェックポイント・統合）では、write-tree の前に、一時 index から秘密の型のパスを除く。照らすのは Intercat の一覧だけで、除くのは基の木に無いパスだけだ。`.git/info/exclude` は便宜で、保証ではない（5・17 節）。
- Commit を受理してから ref を進め終わるまで、統合の仕事は committing だ。その間は Refresh・二つ目の Commit・Discard を拒む（13 節）。
- シートを閉じても（Esc・Close）、統合の仕事は残り、ほかの窓のシートもそのままだ。仕事を捨てるのは、明示の Discard だけだ（13 節）。
- 候補のコミットは、最終のメッセージと hook で一度だけ作り、Check と秘密の検査はその候補にかける。Commit を押しても `git commit` は走らせ直さない（13.3）。木に無い hook は、候補を作る commit の直前に、元と同じ相対位置へ写す。浅い clone には来ないからだ。追跡済みの hook は、統合の木にあるものを使う。写せない hook は黙って飛ばさずにカードで止め、拒否は Check の赤と同じに扱う（13 節・㊻）。
- トラックの記録は二つだ。integrated は中身がどこまで統合先に入ったかで、Commit でだけ進む。base は差分の基点で、Commit と合わせ直しで進む（13.3）。
- Commit の後は、base（今回 Commit に入れたチェックポイント）から次の差分を取る。ワーカーの worktree は、自動では動かさない。
- ディスクと木の一致は、対象の木を read-tree した一時 index に add -A して比べる。チェックポイントの写しは、worktree の実 index の写し（linked worktree では `.git/worktrees/<名前>/index`）から始める。まだコミットしていない `git add -f` のファイルも、落とさないためだ（12.4・13.3）。sparse の型の外の変更も取るため、一時 index では `add --sparse -A` を使う（12.4）。
- worktree を書き換える・消す操作（合わせ直し・古い worktree の削除・Archived の Delete）は、そこで記録した組に生きたプロセスが無いときだけ行う。残っていれば、止めるか待つかを聞く（13.3・21 節）。
- 依存で作った後続は、引き継いだ依存元のチェックポイント（inheritedCheckpoint）を持つ。依存元をそこまで統合した後なら、後続の差分は後続の分だけにする。統合済みかは、git の祖先ではなくチェックポイントの番号で比べる。合わせ直しで、祖先の関係が切れるからだ（10.1・13.3）。依存元が二つ以上なら、共通の祖先を先に進め、残りはそれぞれの L から当てる（13.3）。
- 分岐と依存の後続は、元のチェックポイントの baseAt と baseInheritsAt を一組で写す。依存元の更新を当てたときの inherits は、祖先ごとに大きい番号で併合する（10.1・12.2）。
- 依存元の更新を後続に当てるときの基点は、後続が継いだその依存元の点だ。合わせ直しの基点 L とは分ける（10.1）。
- 既にあるトラックが初めて依存元を継ぐときの 3-way の基点は、継ぐチェックポイント自身の base だ。後続の base は変えない（10.1）。
- 置き換えの記録は、取り消し済みかどうかの印を持つ。次の置き換えは、まだ取り消していない記録だけを取り消す（12.6）。
- 添付の置き場所と入れ子のリポジトリは、チェックポイントと Commit の一時 index から毎回取り除く。ignore は、force-add や否定のパターンで上書きされるからだ（12.4）。
- ワーカーの index に未解決の競合があっても、チェックポイントは作り、パスを記録する（Checkpoint.unmergedPaths）。解くまで Commit は灰だ（12.4・13.4）。
- worktree には自分の変更の全部を運び、base には統合済みのもの（統合先の中身と、自分の統合済みの変更）だけを運ぶ。合わせ直し・Restore・依存の更新・付け替えに共通だ（13.3 の手順 16）。
- Refresh は、走っている処理を止めてから始める。非同期の結果は、始めたときの仕事の版が今と合うときだけ取り込む。Check の結果は、木と検査の設定の組に結び付ける（13 節）。
- 1 トラック＝1 コミットで、分けたりまとめたりしない。まとめると、置き換えの取り消しが別のトラックの変更まで消すからだ（5 節）。件名はリポジトリの規約に合わせ、Signed-off-by のような人の証明はエージェントが作らない。
- git の外へ出た効果（Effect）は、シートに一行で出す。知らせるだけで、止める理由にはしない。
- Push のシートは、送信元の SHA・送り先の集合・宛先 ref を固定する。送り先は書き換えを解いた後の全部で、送る直前に取り直して比べる。タグは送らない（5 節）。
- 統合の clone の LFS の置き場所は専用で、対象の木に要るオブジェクトだけを clonefile で写す。Commit の前に、各コミットが指す実体を元の置き場所へ戻して照らす（13.3）。
- 統合の作業場所は、Check の前後の木の確かめで守る。走査で見つからないことは、止まったことの保証にしない。Check の世代ごとに clonefile で写し、書き込みは世代のパスに限る（13.3、V64）。
- 統合の仕事どうしで共有するのは、中身で決まる取得物だけで、どの仕事からも読むだけだ。cargo の target のような実行できる生成物は、仕事ごとに置く。依存の導入は、スクリプト無しの取得と、仕事の中の `--offline` の導入の二段だ（13.3、V59）。
- tmp は仕事ごとに作り、`TMPDIR` と読み書きの許可をそこに限る。Check・依存の導入・変換にも印を入れ、子孫が止まってから仕事を終える（11.4・17 節）。
- 仮定の Change と秘密の Remove の直しは、今の統合の仕事に入れて Check をやり直す。Refresh は要らない（13.3）。
- 承認・拒否・質問への回答は、その Run が枠を持っていれば使い、持っていなければ取ってから送る。lost では枠を返さず、Stop here か Pick up でホストの終わりを確かめてから返す（15・18 節）。
- Check は終了コードしか分からないので、統合の失敗の行にテストの数は出さない。担当の候補は、差分のあるトラックだ。fix は担当のコミットに入れて後ろを作り直し、合わなければ一つ後のトラックへ移す（13.3）。

### worktree（19 節）

- Reviewerは、対象のチェックポイントと親の木を、Gitの情報を持たない一時ディレクトリへ書き出す。
  読み取り専用のReaderプロファイルで読み、指摘を対象のSHAに結び付ける（19節）。
- 別フォルダの依存参照も保存した木を書き出す。
  書き込みのできるワーカーへ渡すので、HFSXの読み取り専用イメージとしてマウントする（10.1節・V58）。
- codeのworktreeはワーカーごとに持ち、document / page / imageはセッションで共有する。
  共有worktreeの書き込みは、貸し出し（lease）一つで直列にする（19節）。
- 共有 worktree の貸し出しは、前の持ち主の記録した組に生きたプロセスが無いときだけ移す。残っていれば、止めるか待つかを聞く。Export のシートも同じだ（19 節）。
- 依存は worktree ごとに、デーモンが sandbox-exec の中で入れる。プロファイルは Check とは別だ。

### 不可逆な一手を止める（17 節）

- 不可逆かどうかは、LLM ではなくポリシー核のルールで決める。ルールは五種で、サンドボックスの外で走らせる要求・コマンドと引数のパターン・対象パス・通信先・見えない仕事を作るコマンドである。
- 止める対象は、字面ではなく走査で決める。印の環境変数（`INTERCAT_HOST`）と、worktree の中の cwd・開いたファイルの二つだ。印の無いプロセス（人のエディタ）には、信号を送らない。環境を消して worktree の外にいるものは見えない。走査が読む環境変数は `INTERCAT_HOST` だけだ（11.4・㊺）。
- 切り離し（setsid・nohup など）には Allow once を出さない。切り離したプロセスは、組への停止が届かないからだ。代わりに「Run it under Intercat」で、デーモンが組を持ったまま走らせる（17 節・㊶）。
- 外へ出る一手の行は、それぞれ Effect の kind を持つ。その行で止めた呼び出しが許可されて走ったときだけ、Effect を作る（17・16 節）。
- 消されて困るファイルは、OS の書き込み制限で守る。守るのは、秘密の型と、プロジェクトの Protected files の一覧（既定は空）だ。ほかの ignore の対象（ログや生成物）は守らず、消されたら戻らない（17 節・㊷）。
- 削除の行は字面ではなく対象で決め、チェックポイントで戻せない削除を分かる範囲で先に止める。これは補助で、保証ではない。作業ツリーの変更を捨てる git のコマンドも、削除に入れる。止めない削除では、許す前にデーモンが worktree の写しを取る。ワーカーは push しないので、ただの git push も止める。
- 核が見るのは、ワーカーの承認要求だけだ。shell の要求は実行の前に、通信先の要求は接続の前に届き、通信先は宛先だけで決める。
- ファイルの道具の読みと worktree の中の書き込み、web\_search は、承認要求を出さない。秘密ファイル（どの階層にある `.env`・`.env.*`・`.envrc`・`*.pem` など）は、profile の deny で道具から読み書きできなくする。`.env.example` などの例の名前は読める。同じ一覧を、初期コミットの除外と開始元の検査にも使う。Continue を選んだ追跡済みのファイルは、deny から外す。`.npmrc` は既定では止めない。認証情報の鍵があれば、デーモンが見つけて deny に足す（17 節・㉝。M5）。
- 追跡済みの秘密ファイルがあれば、セッションを作る前に止めて聞く（Untrack it / Continue。既定は Untrack it）。木に入っている秘密は、Check から読める。ワーカーも、ファイルとしては読めないが git からは読める（5・17 節）。ワーカーの作業場所を履歴から切り離すのは、後の候補だ（付録 A）。
- Check・hook・依存の導入は、元のオブジェクト DB に届かない浅い clone（`file://`、depth 1）の作業場所で走らせ、履歴の秘密に届かせない（13・17 節）。
- ワーカー自身のテストは、秘密ファイルを読めずに失敗することがある。Check も本物の秘密は読まない。読みを統合 worktree と toolchain に限り、要る値は人が選んだ Check environment を環境変数で渡す（17 節・㉟）。
- 秘密の検査は、公開されるすべてのコミットが対象だ。Commit の各コミットは親との差分で、初期コミットと starting point は木の全体で検査する。結果は、親の木・対象の木・規則の版・秘密の値の指紋に結ぶ（13.3）。ワーカーに渡す Check の出力も隠す（17 節）。検査は Check を待たず、テストコマンドが無くても走る（13.3）。web_fetch も、許可リストの外のホストならセッションに一度聞き、ホストとメソッドを Effect に残す（17 節）。
- 管理の git の操作は、git を起動せずに gix で行う。git の CLI は sandbox-exec の中だけで、プロファイルは五つ（git だけ／チェックポイント／起動を許す／Push／シェル）だ。Push は、pre-push を通信を切って先に走らせ、`git push --no-verify` で確認した送り先にだけ送る。LFS の実体は、その前に `git lfs push` で送る。先に走らせる pre-push には、`GIT_LFS_SKIP_PUSH=1` を渡す。LFS の送り先は `.lfsconfig` まで解いてシートに出す（5 節、V62）。Intercat が作るコミットは署名しない（17 節・㊱）。
- ワーカーが求めた秘密は、MSP で返さず、環境変数でホストに渡す。既定は Keychain に保存してプロジェクトの以後のワーカー全部に渡し、その範囲をカードに書く。「This time only」も選べる。ワーカーからは読めるので、そう書いて見せる。ログには、取り込む時点で伏せて書く。照らすのは値ではなく指紋（HMAC-SHA256 と長さ）なので、値を消した後に resume で戻った履歴も伏せられる（10.1・16 節・㊲）。
- 保護された場所への書き込み（`.muse/`・`.agents/skills/`・Git のメタデータ）は、核がカードにする。M1 から入れる（17 節）。
- 核が止めるのは、認識できる不可逆な操作だ。シェルの命令の字面（ローカルのデータストアの削除やフレームワークのリセットを含む）は止め、プログラムの中からの同じ操作は止めない。画面の約束も、この範囲に合わせる（17 節）。
- プロジェクトの Muse hook は、Intercat が立てる全部のホストで既定で止める。hook は道具の制限にもサンドボックスにも縛られないからだ。要るプロジェクトだけ、中身を見てから設定で On にする（17 節・㊽）。
- 核が止めたカードの答えは、Allow once / Don’t run it / Reply の三つだ。許可するのは Allow once だけで、保留していた同じ命令が走る。Reply は、拒否に文を feedback として添える（ターンを切らない）。拒否も続けさせる応答なので、その Run が枠を持っていれば使い、無ければ取ってから送る（15・17 節）。
- 守りは二重だ。核が承認要求を判定し、Muse のサンドボックスが、核の許した命令の中身を OS で縛る（⑪）。
- デーモンが走らせる Check と git の hook は、sandbox-exec のプロファイルで縛る（㉖）。git の操作も二種に分ける。refs などの管理の操作だけを、リポジトリ由来の設定を読ませずに外で走らせ、リポジトリのコードを動かし得る操作（add・commit・merge-tree など）は中で走らせる（17 節）。

### 上限と失敗（11・18 節）

- done は、終わり方（completed / stopped-by-you / connection lost / cut）で表示を分ける。人が止めたものは緑の ✓ にしない。completed も、最後のターンの Result で分ける。緑の ✓ は done だけで、partial は琥珀の ◐、failed は赤の ✗ だ（11 節）。
- stopped は、人なしには続けられない状態で、そのトラックだけに起きる。理由は stopReason に持つ。統合の失敗は、トラックの状態にしない（11 節）。
- セッションを失ったときの Pick up は、今のファイルを引き継ぐ復旧だ。残った書き込みを止めたと確かめ、今の worktree を写しに取ってから、同じ worktree で始める（18 節）。
- Stop everything は四段だ。新しい仕事を始めない、デーモンの仕事を取り消す（ref の更新だけは終わらせる）、プロセスを止める、次に立ち上げたときは何も自動で投入しない（18 節）。
- デーモンは、起動と正常な終了の印を世代つきで書く。前の世代の終了の印が無い起動では、何も自動で投入しない。ログの障害中に出した停止の意思も、これで守る（18 節）。
- 上限と認証はアカウントの事情なので、新しい仕事の投入を一斉に止める。トラックの見出しは実際の状態のままにし、帯に「New work paused · plan limit until 16:20」の形の一行を出す（18 節）。
- 待ちが長いときは再試行せず、リセット時刻を出して待つ。不可逆な一手の途中で切れたら、自動では再試行しない。
- 再接続は、session/resume と保留中の承認の照合で行い、成功しても何も言わない。古い承認のカードは無効にし、再送は人が決める。履歴は、記録した viewCursor から view/page で読む。止めるのは、目当ての事象に着くか終端に着いたときで、進まないページは誤りとして扱う（SDK と同じ）。新着はページの間は溜め、重複は viewCursor が同じかで消す。省かれた本文は、要るときだけ取る（18 節、V56）。
- ホストは、セッションを作ったときに、持ち主の無いものを一つ先に立てておく。最初に言葉を受けたトラックに渡す。長く動きの無いホストは止め、次の言葉で立て直す（15 節）。
- ワーカーの圧縮は Muse Code に任せ、Intercat はクリップで見せるだけだ。回数が重なったら、要約付きの新しいトラックを提案する。

### カード（10 節）

- Needs you には、人が決めることか、知っておくべきことだけを置く。カードの先頭に、待ちの種類の印（needs an answer / not started / assumed, running）を出す（10.2）。一番重要なカードを、入力欄に一番近く置く。ポインタかフォーカスが Needs you の中にある間は、領域全体の並びを変えない（10.2）。
- 同時に見せるカードの数には上限がある。超えた分は、優先の低い方から「+N more」に畳む。まだ始まっていない依頼（Can’t place）は、提案のためには畳まない（10.2）。
- 提案は七つの場面だけで、同時に一枚だ。場面は衝突・ワーカーの完了・静かな未コミット・Commit の後の Push と PR・圧縮の重なり・残ったシェル・統合で直した箇所の合わせ直しである（9.10）。
- ターンの後に残ったシェルのプロセスは、知らせずに止めず、shell のクリップで見せる。人が止めると、記録したプロセスの組に信号を送る（11.4・⑱・⑲）。
- 仮定のカードの既定は、白ではなく文字のボタンだ。白は、押さないと進まないもの（カードの既定・シートの確定・帯の Start plan）だけに使う（3.3）。
- Reviewer の指摘は、原則としてカードにしない。blocking の指摘は止めずに、「fix: …」の点線としてワーカーに置く。行が変わった後の古い指摘は置かない。照合は、指摘が来た時点と、fix を投入する直前の二回だ。自動の fix はファイルごとに 2 回、トラックごとに 4 回までで、超えたら人に聞く。直ったかは、行の差分ではなく再レビューで決める（10.4）。

### タイムライン（3 節）

- 再生ヘッドは「今」で、人の操作では動かない。選択とフォーカスは、再生ヘッドとは別の状態だ（3.2）。
- ワーカーのクリップは、一歩（モデルの一回の生成と、続くツール呼び出しの束）の単位だ。バーは実時間で伸びる（3.4・16 節）。
- 未来は順序、過去と今は時間だ。再生ヘッドの右には目盛を出さず、点線のクリップは同じ幅のタイルで順に並べる。どの幅でも各レーンの先頭の項目を見せ、依存は「after A」の札と、選んだときの連結線で示す（3.4）。
- 24px の押せる範囲を隣と重ならずに取れないクリップは、一つだけでも、隣と札にまとめる（3.4）。
- You の列で押せる範囲（24px）が重なる言葉は、一つの押せる組にし、「4 messages」のように数を出す。菱形は一つずつ残す（3.2）。
- 時刻は二つ持つ。日時は epoch、経過は眠りも数える単調時計だ。OS が時刻を戻しても、バーは負にならない（16 節）。
- 離席から戻ったら、Editor の行に一言だけ出す。カードにはしない（3.4）。
- 舞台では、↑ ↓ で全トラックを一本ずつ選べる。画面の外ならスクロールし、選んだ行は仮想化で外さない。1–9 は近道だ。M1 から、行の名前と状態を VoiceOver に出す最小の鏡を持つ（3.4）。

### 言葉の状態（8 節）

- 言葉の状態は、heard → screened → reading → placed → landed の順に進む。landed には、その言葉の userMessage の item が届いたときに移す。人の操作のたびに version を進め、古い version への判定は捨てる（17 節）。
- まだ送っていない言葉は、どの状態からも Take back できる。言葉は捨てない。⌘Z は、タイムラインの編集を、時間ではなく状態で、新しい順に遡って戻す。⇧⌘Z でやり直す（21 節）。
- 合図を待つ言葉（when-told）は「waiting for your go · Start」で待ち、「今やって」（start-waiting）でも始まる。「held · Start」はボタンだけだ（9.3）。
- park は状態ではなく、判定の値だ。行き先なしで帯に残り、次の発話のたびに読み直す。読み直しは新しい言葉の判定の後に回し、新しい順に三つまでだ（8.4）。

### データ（16 節）

- 受信が保存を超えても、stdout は読み続ける。承認もターンの終わりも stdout から届くからだ。まず表示用の delta を落とし、溢れたらそのターンを止める（17 節）。
- 外へ送る命令は、新規の実行と停止に分ける。新規の実行はログに書いてから送り、書けなければ送らない。停止はログを待たずに送り、記録は後から補う。新規の実行は、書き終わりをループに返し、送る直前に条件を確かめる。条件は、ターンの開始・承認の応答・確定済みの ref の更新で分ける。保留が理由なら言葉を待ちに戻し、版の変更か取り消しなら捨てる（17・18 節）。
- 真実の源は、一本のイベントログだ。ホストから受けた MSP のフレームを、そのまま入れる。状態は (Muse のセッション, item) ごとに、新しい revision で上書きする。resume の履歴は、新しい item として足さない。
- SQLite は、アプリ全体で一つ持ち、プロジェクトは列で分ける。リポジトリには置かない。Move to project は、project_id の更新一つだ。一日一回、backup API でバックアップを取る（16 節）。
- ファイルは「＋」でもドロップでも添付できる。落とす先で宛先が決まり（入力欄・帯は次の言葉、レーンはそのトラックだけ、カードはその返答）、扱いは「＋」と同じだ。フォルダを落とすと、プロジェクトに足すかを聞く。大きさの上限は、1 ファイル 25 MB（超えたらフォルダの中のものは参照だけ）、参考に渡す画像 10 MB、一つの言葉の合計 100 MB、貼り付け 2 MB だ。Intercat が作るコミット（初期コミットと starting point）は、1 ファイル 50 MB までだ（3.2）。
- 添付と長い言葉の原本は、アプリのデータ領域に置く。worktree には、Git から外した写しだけを置く。
- Effect はワーカーが git の外でしたこと、Mark は人がアプリでしたことだ。

### ハッカソンで作るもの（6・14 節）

- 成果物は code / document / image の三つで、page は Publish にホスティングが要るので将来に回す。提出に入れるのは code だけで、document と image はマイルストーン 8 だ（2026-11-03 のレビュー）。Image トラックは、Muse Image を Model API で直接呼ぶ。Export は、共有 worktree の最後のチェックポイントを固定して変換し、原稿と PDF を一つの版にする（14 節）。
- 画像の版は、生成が終わるたびに確定する。最後のチェックポイントの木に画像の blob を足して作り、Export は、原稿が参照している版を使う。新しい版は、文書のトラックの点線「use cover v3」で取り込む（6・14 節）。
- 調査から今作るもの・決定だけのもの・後に回すものは、設計書の付録 A に並べてある。

### キャラクター（4 節）

- 箱が猫で、Editor の顔だ。話すのは、初回、自分でしたことか見届けたこと、タップされたときの三つの場面だけだ。
- 言葉を置いたときは頷くだけで、見ていない間の台詞は溜めて戻ったときにまとめる。猫の一言は飾りで、承認・秘密・費用・失敗・質問はカードと通知が全文で持つ。
- 動きは Rive で作る。8 状態を状態機械として持ち、コードから状態を切り替えられるからだ（4 節）。

### 言語・アクセシビリティ・プライバシー（3・7・17 節）

- 初回の準備は二段だ。テキストで始めるには Muse Code と Meta のサインインで足りる。声と画像は Optional にまとめる。ローカルの Editor（Glimmer）は、テキストだけでも必須だ（7 節）。
- 録音中と確定待ちは、Cancel と Esc で取り消せる。取り消す前の音声は、もう Meta に送られている（22 節）。
- UI の言語は macOS のロケールに従い、v1 は en / ja だ。v1 の外観はダーク固定にする（3.6・3.3）。
- タイムラインは GPU で描くので、不可視のアクセシビリティ木を並行に持つ（3.4）。
- UI の倍率は、時間軸のズームとは別に、⌃⌘= / ⌃⌘− / ⌃⌘0 で変える。既定の窓で 200% にしても、内容と機能を失わない。拡大中は、メイン列とレーンの下限を外し、サイドバーを閉じる（3.3）。
- 灰色の文字の色は三段（主・副・注）だけにし、どれも背景とのコントラスト比 4.5 以上にする。状態を示す輪郭（選択・フォーカス、点線の未来、中空の止まったクリップ）は 3 以上にする。弱めるときは、暗くせず、形と書体で示す（3.3）。
- 使用統計は取らない。クラッシュ報告は、人がオンにしたときだけ送る（7 節）。
- 描く側にも境界を置く。Markdown はサニタイズし、外部の画像は自動で取りに行かない。load とリンクは、開く前に URL の全文をゲートの検出に通す。URL そのものが秘密を運び得るからだ（15 節）。
- 打ち出しは「何が Mac の外へ出るかを、常に見せる」だ。Privacy gate が調べるのは文字だけで、声の原音は文字起こしのために Meta へ出る（17 節）。長い入力も全文を調べ、ワーカーにはマスク済みの写しを渡す。

## 評価

「操れる」を数字で示す。同じ 3 トラックの課題を、「Muse Code の TUI 3 枚」と「Intercat」で各 3 回行う。

- Intercat の側も、トラックは手で立てる（New track と fork）。Planner の分解はマイルストーン 3 なので、使わない。
- 三本が同じファイルに触れてもよい。Commit で衝突したら、止めてカードで外す形が提出に入っている（[docs/milestones.md](milestones.md) の提出までの順）。

- 測るのは、介入の回数、気づいてから介入するまでの遅れ、誤って走った手の数だ。
- 点線を切って走らせなかった手も数える。切った点線の数と、そのトラックのターンの中央値から、省いたトークンを見積もる。
- 誤りに気づけたかと、狙った作業を止められたか（声とキーで同じ対象へ）も見る。どちらも、完成した量とは分けて測る。
- 声は、⑨ の数字で文字入力と比べる。
- Intercat の側はイベントログから集計し、仕組みはマイルストーン 1 に入れる。TUI の側は、同じ項目を手で記録する。
- 根拠の無い反論の後に、正しかった行が書き換わった数も数える（設計書 17 節の評価）。
- n は小さい（各 3 回）。そう書いて出す。
- 結果は、動画の最後の 10 秒に一枚で出す（[docs/milestones.md](milestones.md) の動画）。
